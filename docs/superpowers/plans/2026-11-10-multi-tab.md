# Multi-tab Documents Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give M Note native macOS tabs: one tab per document, opened from Finder, the CLI, links and drops, with Cmd+T/N/W and Cmd+Shift+[ ] to move between tabs.

**Architecture:** Each document stays its own `BrowserWindow` (so the per-window save-before-close and update flows remain unchanged). A new main-process module, `document-windows.ts`, owns the document registry: file path, dirty state, untitled number and focus history. It decides where each document opens and groups windows with `addTabbedWindow`, using pure decision functions in `document-tabs.ts`. The main process now owns window titles. The renderer reports dirty state over IPC and asks the main process for a Save As path.

**Tech Stack:** Electron 42 (`BrowserWindow.addTabbedWindow`, `Menu` roles `selectNextTab`/`selectPreviousTab`), React 19, Vitest 4 + jsdom.

**Spec:** `docs/superpowers/specs/2026-11-10-multi-tab-design.md`

## Global Constraints

- `tabbingIdentifier: 'm-note'` on every document window. Tabs are forced by calling `anchor.addTabbedWindow(newWindow)`, whatever the macOS "Prefer tabs" setting says.
- Shortcuts:
  - `CmdOrCtrl+T` and `CmdOrCtrl+N` both open a new tab.
  - Close uses `role: 'close'`, which is Cmd+W.
  - `Cmd+Shift+[` maps to `selectPreviousTab` and `Cmd+Shift+]` to `selectNextTab`.
  - There is no Cmd+1…9.
- The application menu must keep `appMenu`, `editMenu` (copy/paste) and `viewMenu` (Cmd+R reload; see `cmd-r-reload.test.ts`).
- Title strings, exactly: `Untitled`, `Untitled 2`, `Untitled 3`, … using the lowest free number. A saved document shows its file name (basename). Unsaved changes add the prefix `● ` (U+25CF and a space).
- The Save As dialog uses `defaultPath: 'Untitled.md'` and `filters: [{ name: 'Markdown', extensions: ['md'] }]`, the same as `window-close-handler.ts`.
- `update-session.json` must still read the legacy format, a plain `string[]`, because the version you upgrade *from* writes it.
- Closing the last tab still quits the app. Don't change the `window-all-closed` handler.
- Code style: no semicolons. Single quotes in `src/*.ts` main-process files and double quotes in `.tsx` component files, matching each file's neighbours.
- `CLAUDE.md` rule: write the test first, and watch it fail, before the code.
- No Playwright and no new dependencies.

## Review Focus

1. **Upgrading from a pre-tabs version.** The old app writes `update-session.json` as `["/a.md","/b.md"]` and the new app reads it, so both documents must reopen. Covered by the Task 2 test `reads the legacy array format`.
2. **The same file under two spellings**, for example a relative CLI arg or `/x/../a.md`. It should focus the existing tab, not open a duplicate. Covered by the Task 1 test `matches the same file under a different spelling`.
3. **The last-focused window has been closed** when a Finder open arrives. The new document must not call `addTabbedWindow` on a destroyed window. It joins another open window, or stands alone if none is left. Covered by the Task 3 test `falls back when the last focused window has closed`.
4. **Reusing an unedited Untitled tab that is still loading.** `file-opened` must arrive after `did-finish-load`, not be lost. Covered by the Task 3 test `defers file-opened until a reused tab finishes loading`.
5. **Cmd+Q pressed again while a save prompt is open.** There must be no second round of prompts. Covered by the Task 5 test `a second quit while prompting reuses the first`.

**Interfaces:**
- Consumes: Task 1 (`chooseOpenTarget`, `nextUntitledNumber`, `tabTitle`, `TabDocument`) and Task 2 (`UpdateSession`).
- Produces:
  ```ts
  export interface DocumentWindows {
    open(filePath: string, anchor?: BrowserWindow | null): BrowserWindow
    newTab(anchor?: BrowserWindow | null): BrowserWindow
    setFilePath(webContentsId: number, filePath: string): void
    setDirty(webContentsId: number, dirty: boolean): void
    filePathOf(window: BrowserWindow): string | null
    isDirty(window: BrowserWindow): boolean
    anchor(): BrowserWindow | null
  }
  export function createDocumentWindows(makeWindow: () => BrowserWindow): DocumentWindows
  ```
  Import only the `BrowserWindow` *type* from `electron`. `makeWindow` is injected so the module can be tested without mocking Electron.

What the module does:
- Registers each window under `webContents.id`.
- Tracks the last focused window from each window's `'focus'` event.
- Removes a window from the registry on `'closed'`.
- Cancels `'page-title-updated'` with `event.preventDefault()` and calls `setTitle(tabTitle(doc))` whenever a document changes.
- Sends `'file-opened'` with the path on every `did-finish-load` (keeps Cmd+R reload working).

`anchor()` returns the first of these that applies:
1. the last focused window, if it isn't destroyed
2. the most recently registered window that isn't destroyed
3. `null`

A new window is attached with `anchor.addTabbedWindow(win)` when an anchor exists.

How `open` handles each `chooseOpenTarget` result:
- `focus`: call `focus()` on that window.
- `reuse`: set `filePath` and clear `untitledNumber`, update the title, then `focus()`. Send `'file-opened'` now unless `webContents.isLoading()` is true; in that case `did-finish-load` sends it.
- `new`: create, register and attach a window.

**Interfaces:**
- Consumes: `documents.isDirty` from Task 3.
- Produces: `export function prepareWindowsForQuit(windows: BrowserWindow[], isDirty: (window: BrowserWindow) => boolean): Promise<boolean>`

How it works:
- Go through the windows in order and skip destroyed ones.
- If `isDirty(window)`, call `window.focus()` before `prepareWindowForClose(window)`.
- When a window is ready, call `approveWindowClose`.
- If any window returns false or throws:
  - `resetWindowClose` every window
  - show `dialog.showErrorBox('Unable to save', message)` (only when it threw)
  - resolve `false`
- While a call is in progress, later calls return the same promise.

The new `before-quit` handler:

```ts
let quitApproved = false
app.on('before-quit', (event) => {
  saveWindowBounds?.flush()
  if (quitApproved || isInstallingUpdate()) return
  event.preventDefault()
  void prepareWindowsForQuit(BrowserWindow.getAllWindows(), documents.isDirty).then((ready) => {
    if (!ready) return
    quitApproved = true
    app.quit()
  })
})
```
